# Vixel Creator MCP tool contract

Status: generated release-candidate contract for plugin `1.0.0-alpha.10` and MCP contract `film-v1`.

Do not edit this file in the distribution repository. It is generated from the
registered tools in the canonical Vixel product repository. The exact JSON
schemas and annotations are in [`contract/tool-surface.json`](../contract/tool-surface.json).

## Connection

- Endpoint: `https://drama.vixelai.com/api/mcp`
- OAuth scopes: `film.read`, `film.write`, `film.generate`, `offline_access`
- Tool count: 42
- Tool-schema SHA-256: `ede498f56a17e145322f9565985fe1986813972ec96d9bac4cd79970644398c3`

The MCP endpoint is the RFC 8707 OAuth resource. The plugin intentionally does
not set an `oauth_resource` override because Codex/rmcp derives the endpoint
resource during discovery.

## Canonical rules

- The authenticated Vixel Work graph is the sole production truth.
- Writes use exact `expectedRevisionId` / `expectedWriteVersion` and stable keys where required by the registered schema.
- Save the canonical Script before the initial Elements/Shots. Use the same Work in CLI, MCP and browser.
- Generation requires a fresh quote, explicit budget and stable key; recover the original Job.
- Asset review is an explicit creator decision. Timeline edits return canonical receipts.
- Export manifests describe the accepted first-route cut. Local CLI rendering is not a server Job.
- Prepared releases are not published posts. Social publishing and audience metrics remain unavailable.

| `film_v1_production_quote` | `film.read` | `read` | none | Quote an image or video for an exact Element or Shot of the Work. What works best on the video model, from its own prompt guide (a guide, not a rule): first the line `For the target video, at 0.00 seconds into the target video, <Picture 1> (from [Shot 1]) is fully referenced.`, a blank line, then `integrated_multimodal_description: [Shot 1] …` opening with the art style and the opening frame's subjects and composition, then the action in time order (a later cut as `[Shot 2] At 00:03.500, the camera cuts to …`; camera as motion type plus amplitude and speed, such as `pushes in with large amplitude at medium speed` or `tracks left beside her at walking speed`; each speaker named once with an ID like (S1) and their approved line word for word as <d>[Chinese] …</d>), then `overall_soundscape: …` (ambience, action and wordless sounds) and `non_diegetic_music: …` (N/A when none). Keep the timeline within the Shot's duration and prefer concrete sights and sounds over words like cinematic. Only a video quote without videoPrompt falls back to a take Vixel compiles from direction and the plan, with its own fixed sentences (the exact scripted words, the first frame's identities and no on-screen text); there videoDirection sets that take's camera, action and/or sound (ambience, effects and wordless vocal sounds), an omitted camera or action keeps the Shot's current one and an omitted sound keeps the planned sound. For an image, direction is this take's brief for pose, expression, camera, framing, look and lighting; the identities, the frame shape and no on-screen text stay fixed. An Element image can take referenceAssetIds: images uploaded to this Work, such as the creator's own illustration; say in direction who or what in them this Element is. A Shot opening image can take referenceAssetIds too: extra accepted images of this Work it must match, such as the creator's own model art; say in direction what each one is for. An image take without editAssetId redraws the target from its looks and plan, so it never sees an earlier image. To change one detail of an existing image (wrong scale, a drifted prop, style slips) and keep the rest of it, pass that image as editAssetId (the target's current image or an earlier take of it) and say only the change in direction; a Shot edit may add accepted Element looks as referenceAssetIds to match, such as a character sheet. Media comes in two tiers, Standard by default: an image at options.quality medium or high (HD), a video at options.resolution 768P or 2K (HD, sharper than 1080p, twice the price per second). The quote lists both tiers with their credits in tiers; offer HD when the creator asks for higher quality, 1080p or HD, and quote again with the chosen option before submitting. To remake existing footage (a reference video), cut one 1-15 s window of it (H.264 MP4, at most 32 MB), upload it to the Work (upload_intent with mimeType video/mp4 and durationMs, then upload_finalize) and pass its assetId as options.referenceVideoAssetIds on a Shot video: the take recreates that window's shots, camera, cuts and choreography, with the Shot's accepted looks (and its accepted opening image, if it has one, which then shows the cast in that setting) in place of the original subjects. Placing a narration line makes narration its voice even if the plan says video: the Shot's videos then leave it out, and one made with the line spoken becomes outdated. No Job, crop, mutation or charge. |

## Compatibility and release

The source repository owns server implementation, schemas, scopes, and the
canonical plugin source. This repository is a source-free Marketplace and
installation mirror. A release is acceptable only when its provenance and
bundle hashes pass CI against this generated contract.

Production OAuth deployment and a real signed-in Codex acceptance are separate
release gates. An RC bundle does not claim that those gates have passed.
